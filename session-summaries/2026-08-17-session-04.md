## Mobile-first responsive approach (important design decision)

Brandon asked to support **all Chrome DevTools device presets, mobile-first**. Key reasoning captured for the next session:

- Tailwind breakpoints are min-width/mobile-first. **Everything below `sm` (640px) shares the base (unprefixed) styles** — so every phone preset (Galaxy Fold 280px, iPhone SE 375px, Pixel 5 393px, S20 Ultra 412px, Surface Duo 540px) gets the same base layout. The base styles had to work at the **narrowest** (280px) to be safe.
- **Recommendation Brandon accepted:** don't cram all 15 images onto a phone — show only **3 core images** (eggwich, lox, turkey) as small `w-16` accents on mobile, keep text as the focal point, and **progressively reveal** the rest at `sm`/`md`/`lg`. Trade-off acknowledged: less "busy collage" fun on mobile, but readable and uncluttered.
- Implementation pattern: mobile-visible images use base classes then scale up (`sm:w-44 md:w-52`); the rest are `hidden md:block` / `hidden lg:block` / `hidden sm:block`. `tuna-salad` moved to `hidden sm:block`. The mobile-only heavenly-veggie uses `sm:hidden`.
- **Not yet visually verified by a human across the presets** — this was built blind (Claude can't drive the DevTools device toolbar). **Next session should click through the presets**, especially 280px Galaxy Fold (tightest), and flag overlaps/crowding.
