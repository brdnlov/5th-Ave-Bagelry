## Environment traps hit this session (read before debugging anything)

Session 6 documented three. This session found four more, and two of them produced *confidently wrong* measurements that would have shipped bugs.

1. **`mobile: true` in `Emulation.setDeviceMetricsOverride` corrupts `innerWidth`.** Setting width 320 with `mobile: true` made `window.innerWidth` report **472**. Because the overflow check is `scrollWidth - innerWidth` and both came from the same inflated viewport, it cancelled to zero and reported "no overflow" on a page that had **151px of real horizontal overflow**. Always pass `mobile: false` with explicit `screenWidth`/`screenHeight`, and assert `o.vw === requestedWidth` in the probe itself. Session 6's `--window-size` trap is the same family: the browser will happily lie about the viewport.

2. **`deviceScaleFactor: 2` does not drive `srcset` selection in headless Chrome.** A DPR-2 pass reported *every* image on the site as under-resolved, which would have implicated `next/image` itself. The emitted markup was correct all along (`w=48 1x, w=96 2x`). Check the `srcset` attribute in the HTML, not `naturalWidth` under emulation.

3. **`scrollWidth > clientWidth` is a bad "clipped content" heuristic.** It false-positives on two legitimate patterns used all over this codebase: `sr-only` (which clips to 1px by design) and any `position: relative` box with absolutely-positioned children that overhang on purpose. Verify by measuring the child against the *section* bounds, not its immediate wrapper.

4. **A trailing space after a CSS hex escape is eaten as the escape terminator.** `content: "\2733 "` renders as `✳` with no trailing space. Use `\20` for an explicit space, or a literal character.

Carried over and still true: **never kill Chrome or node by image name.** Kill the PID bound to the port, or use CDP `Browser.close`. Note `rm -rf` on a Chrome profile fails with "Device or resource busy" if the browser is still running — close it via CDP *first*, or just use a fresh profile directory.

## Framework findings (verified against this install, not training data)

**Tailwind 4.3.3** — all confirmed by compiling a probe through `@tailwindcss/postcss` rather than assuming:

- `bg-radial-[at_50%_0%]` exists and compiles to `background-image: radial-gradient(var(--tw-gradient-stops, …))`. Composes with `from-*`/`to-*` and stacks with a `bg-<color>` because they set different properties.
- `columns-1` / `columns-2`, `break-inside-avoid`, `line-clamp-8` all exist.
- **`--theme(--color-brand-tan)/15` inside an arbitrary value silently compiles to `#D99B5A/15`, which is invalid CSS**, so the browser drops the whole declaration. An 8-digit hex works. The `from-brand-tan/15` utility form avoids the trap entirely.
- `content: "✳" / ""` — the CSS alt-text syntax — compiles and works, giving generated content an empty accessible name.
- The default `transition` property list includes `--tw-gradient-from/via/to` (relevant to the session-6 `--bite-radius` override trap).

**Next.js 16.3.1:**

- Static `export const metadata` is the documented form for a route with no dynamic data; `generateMetadata` is for routes that fetch. `CLAUDE.md`'s "use generateMetadata" note predates having a static route.
- JSON-LD guide (`node_modules/next/dist/docs/01-app/02-guides/json-ld.md`) recommends a `<script type="application/ld+json">` in the page, with `JSON.stringify(...).replace(/</g, '\\u003c')` for XSS hygiene.
- `next/image` **refuses SVG** unless `dangerouslyAllowSVG` is set in `next.config`. For a single icon, inline the SVG instead — no config change, no extra request.
- eslint's `@next/next/no-html-link-for-pages` fires on `<a href="/">`; internal navigation needs `next/link`.

**JSX:** `{/* comment */}` is only valid in children position. Inside `cond && ( … )` before the element, it is a syntax error — use a plain `/* */` JS comment there.

## The one real bug of the session

`/menu` had **151px of horizontal overflow at 320px** and again at 640px, and the first audit missed it entirely because of trap #1.

**Root cause:** React renders adjacent list items with no whitespace between them — `<li>8 Grain</li><li>Egg</li>` — and the asterisk separator's gap was `margin-inline`, which is **not a line-break opportunity**. The only breakable points were *inside* multi-word names, so the whole 25-item run became one unbreakable word. Its min-content width became the grid column's floor, and the column pushed past the viewport.

It looked fine at 1280 purely because the column happened to be wider than the run.

**Fix**, in `globals.css`:

```css
content: "\A0\2733\20" / "";
```

Both spaces are load-bearing and *different on purpose*. `\A0` (non-breaking) glues the asterisk to the item before it so a wrapped line ends with "✳" like it would end with a comma. `\20` (ordinary) is the actual break opportunity. Also moved `display: inline` off the `<ul>` so it stays a block container — `text-wrap: pretty` is inert on an inline element.

## Judgement calls worth remembering

**Refused: writing the reviews.** Inventing customer quotes attributed to named people on a real business's live site is fabricated testimonial content. Also declined to scrape — both platforms prohibit it and both have official APIs. `Reviews.tsx` renders nothing while `REVIEWS` is empty and contains no placeholder copy, so the section is *incapable* of shipping invented testimonials.

**Refused: drawing the platform logos.** A from-memory reproduction of the Instagram glyph or Yelp Burst gets corner radii and proportions subtly wrong, which for a trademark looks cheap *and* is a misuse. Resolution: took the **official** Instagram path data from the `simple-icons` package, installed with `--no-save` and deleted afterwards — `package.json` and `package-lock.json` untouched, no dependency added. The glyph stays black and does **not** inherit `currentColor`, because Meta permits black/white/gradient and forbids arbitrary tinting.

**No `aggregateRating` JSON-LD.** Google's policy forbids marking up ratings collected from Google, and self-serving review markup is a manual-action risk. The `Menu` and `Bakery` blocks carry no ratings.

**Hours were left `null` until Brandon supplied them.** Nothing in the repo recorded opening hours; an absence beats an invention on a shopfront page. Now set to Mon-Sun 6:00AM–3:00PM — **still worth confirming against the shopfront**, since it is the one fact on the site not checkable from anything in this repo, and it is now in structured data where being wrong is more costly.

**The Social CTA was built, then deleted.** It read as filler: Yelp is not something you follow, the footer already carried both links, and Reviews linked Yelp twice more. The Instagram handle folded into Location instead — "come see us" and "follow us" are one thought. Net effect was removing a section rather than adding one.

## Accessibility work (step 9, largely done as we went)

Both routes measured at 13 widths from 320 to 768, in interactive states as well as at rest.

| | HOME | `/menu` |
|---|---|---|
| Horizontal overflow | none | none |
| Contrast failures | 0, worst 4.56 | 0, worst 4.56 |
| Tap targets < 44px | 2 | **0** |

HOME's two are the inline Yelp/Google credit links in the reviews footer — WCAG 2.5.8 exempts links inside a block of text, and both destinations are reachable at 44px from the ratings row above. Stacked, padding them would make their hit boxes overlap *each other*.

**Contrast erosion is the recurring hazard.** A `bg-brand-charcoal/5` card tint darkens the ground just enough to break text that passes on plain cream:
- `text-brand-brown/70` → 3.59:1 on cream (fixed to `/80`)
- `text-brand-brown/70` → 4.52:1 on a tinted card (fixed to `/80`)
- `text-brand-red` → **4.11:1** on a tinted card (fixed by removing the tint from Social cards)

Measure text against the *composited* background, never the token.

Other fixes: navbar "Menu" was 42px wide at the 768 breakpoint (now 66 via `px-3 -mx-3`); footer links were 44 tall but 28–39 wide (`-mx-2 px-2`); the reviews' per-review attribution link went 20px → 44px.
