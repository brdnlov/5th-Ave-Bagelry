## Environment traps hit this session (read before debugging anything)

Three separate times, a tool lied and sent me chasing a bug that did not exist. All three are reproducible, so expect them:

1. **The long-running dev server on port 3000 serves stale Tailwind CSS.** After editing a component to use a *new* utility class, the dev stylesheet did not regenerate it. `[--bite-radius:1.3rem]` was present in the JSX and in the production CSS, but the dev CSS still contained only the `group-hover:[--bite-radius:1.3rem]` rule from the previous edit. Measuring against `localhost:3000` reported `--bite-radius: 0px` and I nearly concluded Tailwind v4 does not support arbitrary custom-property utilities. **It does.** Verify against a production build, or restart `npm run dev` after introducing a new utility.

2. **`chrome --headless --screenshot --window-size=390,1800` does NOT emulate a device.** It produced a screenshot that looked catastrophically clipped — text cut off mid-word, images running off the right edge. There was no bug. You must use CDP `Emulation.setDeviceMetricsOverride`. Session 5 established this; I re-learned it the hard way.

3. **Chrome `--screenshot=<path>` needs an absolute Windows-style path.** A relative path fails with `Access is denied. (0x5)` even when the directory is writable.

Also carried over and still true: **never kill Chrome or node by image name.** Kill the PID bound to the port (`netstat -ano | grep :3100 | grep LISTENING`) or use CDP `Browser.close`. Every `next start -p 3100` test server this session was stopped by PID and the dev server on 3000 was verified alive afterward.

## Verification approach that worked

The pattern from session 5, extended. Scripts live in the session scratchpad; re-create as needed.

- `npm run build`, then `npx next start -p 3100` (3000 is the dev server).
- Launch `chrome.exe --headless=new --remote-debugging-port=9222 --user-data-dir=<scratch>`.
- `PUT http://127.0.0.1:9222/json/new?about:blank` for a `webSocketDebuggerUrl`; Node 24 has a global `WebSocket`.
- Drive with `Emulation.setDeviceMetricsOverride`, `Emulation.setTouchEmulationEnabled`, `Runtime.evaluate`, `Input.dispatchTouchEvent`, `Input.dispatchKeyEvent`.
- **Always `await document.fonts.ready` before measuring text.**

New this session:

- **Measure instead of screenshot.** Returning numbers (widths, heights, `scrollWidth - innerWidth`, computed properties) is faster to read, unambiguous, and does not require the user to eyeball anything. A button that wrapped to two lines showed up instantly as `h=72` against an expected 48.
- **Compute contrast from painted pixels, not parsed CSS.** Tailwind v4 compiles `text-brand-cream/70` to `color-mix(in oklab, ...)`, so any `rgb()` regex returns garbage — my first attempt reported every ratio as `null`. The fix: paint the background chain and then the text colour onto a 1×1 canvas and read the composited pixel back with `getImageData`. This resolves *any* colour syntax and handles alpha compositing for free.
- **React batches state updates, so `element.click()` followed immediately by a DOM read sees the OLD DOM.** This silently made a mobile-menu contrast check report "0 failures" while actually measuring nothing. Await two `requestAnimationFrame`s before reading.
- **`element.focus()` succeeds on `tabIndex="-1"` elements**, so it is worthless as a test of tab-order participation. Assert on `el.tabIndex` instead.

## Framework findings (verified, do not trust training data)

- **Next.js file-based metadata:** `favicon` must be `.ico` and may only sit at `app/` top level; `icon` accepts `.ico/.jpg/.jpeg/.png/.svg` anywhere under `app/**`; `apple-icon` accepts only `.jpg/.jpeg/.png`. Docs: `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/app-icons.md`. `sizes="any"` is emitted automatically for `.svg` icons.
- A file at `app/app/icon.svg` is treated as the icon for a `/app` **route segment**, not the site. It must be `app/icon.svg`.
- **Tailwind v4 `blur-sm` is 8px**, not v3's 4px (v4 added `blur-xs` at 4px). Confirmed in `node_modules/tailwindcss/theme.css`.
- **Tailwind v4's default `transition` property list includes `filter`, `opacity`, `transform`, `pointer-events` and `display`** — so a bare `transition` covers a blur-plus-fade. But it therefore **overrides** a components-layer `transition: --bite-radius 0.25s`, because utilities come after components. Putting `transition` on a `.bite-hover` element silently kills the bite animation.
- **Arbitrary custom-property utilities (`[--bite-radius:1.3rem]`) do work in v4** — see trap #1 above.
- Client Components do not make a route dynamic. The page stayed `○ (Static)` after `Order.tsx` gained `"use client"`.

## Order section rebuild (committed in `a127f16`)

Went through three designs in one session. Final state:

**Structure.** One charcoal panel (`overflow-hidden rounded-[2rem] bg-brand-charcoal`) containing a 3-column grid. Columns are separated by hairlines (`divide-y` stacked, `md:divide-x md:divide-y-0`), not individual cards. Earlier iterations — full-bleed logo cards, then cream cards inside a dark wrapper — were both discarded.

**Why it changed at all.** The original section's two largest colour blocks were Uber's black and DoorDash's orange-red, full-bleed. It read as partner advertising, and DoorDash's `#FF3008` sitting directly above the brand red looked like a rendering mistake. Logos are now contained app-style tiles (`h-24 w-24 rounded-2xl object-contain lg:h-28 lg:w-28`).

**Third option added.** Phone pickup on `tel:+15624996889` with an inline takeout-bag SVG on a brand-red tile. Four icon candidates were rendered and compared (bagel mark / takeout bag / coffee cup / storefront); Brandon picked the bag. Heading changed to **"Order Your Way"** since "Delivery Services" no longer described it.

**Interaction.** Each column is a `<button>` that reveals its CTA over blurred content (`scale-95 opacity-40 blur-sm`). Mouse users get it on `pointerenter`/`pointerleave` (guarded to `pointerType === "mouse"`); touch and keyboard toggle by activating the column. A `document` `pointerdown` listener — attached **only while something is open** — dismisses on a tap outside `panelRef`. Escape does the same for keyboard users.

**Non-obvious constraints baked into the markup:**
- The CTA link is a **sibling** of the button, not a child. A link inside a button is invalid HTML and browsers actively unnest it.
- The link carries `tabIndex={-1}` and `aria-hidden` while hidden, so it stays out of the tab order until revealed.
- Column content uses `<span>`s rather than `<h3>`/`<p>`, because `<button>` may only contain phrasing content. **This cost the section its `h3` headings** — a document-outline regression worth revisiting.
- The reveal is centred by a full-size flex overlay, **not** `left-1/2 -translate-x-1/2`. An absolutely-positioned element with `left-1/2` shrink-wraps to the space between the 50% mark and the right edge (192px), and "Order on DoorDash" needs ~194px — it wrapped to two lines on desktop only. Caught by measuring, not by looking.
- The bite is driven by `isOpen`, not `:hover`. **A phone has no hover, so the notch would never appear on mobile.**

**Pills now match the hero/navbar recipe exactly:** `bite-hover inline-flex min-h-12 items-center rounded-full bg-brand-red px-6 py-3 text-brand-cream`. Measured identical at 24px padding / 16px font / 48px tall. An earlier `px-4 text-sm` variant was a defensive move against an `md` width squeeze that measurement later proved was not real.

**Responsive pass to match the Hero:** progressive type and spacing (`py-16 sm:py-20 lg:py-24`, `text-3xl sm:text-4xl lg:text-5xl`), `max-w-6xl` so Order and Hero share content edges down the page, and **`scroll-mt-20`** so nav clicks do not land the section under the 80px sticky header.

**Measured results** (production build, CDP, 11 widths from 320 to 1440): no horizontal overflow anywhere, no text wrap anywhere, all pills exactly 48px tall, columns equal width (240px at 768, 384px at 1280) and equal height. Tap-outside dismissal verified with real `Input.dispatchTouchEvent` at 390px, including the critical case that a touch **on** the revealed link does not dismiss it before navigation.
